# 优化方法说明

## 1. 背景与问题

对于本次目标模型这类 VLM 多模态模型，`prefill` 阶段正在成为整体推理延迟的主要瓶颈。

其核心原因有两点：

1. 图像侧 `mmproj` 路径本身包含大量矩阵乘法计算，耗时显著。
2. 图像经过视觉编码与投影后，会生成较多视觉 token，这些 token 进一步增加了后续 `prefill` 的计算量，从而拉低整体 `prefill` 吞吐。

因此，相比只优化文本解码阶段，优先降低 `mmproj` 的计算时间，对提升端到端 VLM 推理性能更关键。

## 2. 总体思路

我们的优化思路是：

- 针对 `mmproj` 中占主导的 `mulmat` 算子进行硬件加速。
- 使用基于脉动阵列（systolic array）的 NPU 承担主要矩阵乘法计算。
- 在保证模型可用精度的前提下，对部分精度不敏感的 `mulmat` 层做静态量化。
- 将量化后的算子卸载到 NPU 上执行，CPU 负责调度、同步和少量后处理。

## 3. 为什么选择 NPU 加速 mmproj

`mmproj` 主要由大量线性层组成，本质上是高密度的矩阵乘法。

这类计算具有以下特点：

- 乘加规模大
- 数据访问模式规则
- 算子结构稳定
- 适合做静态编排和 tile 化执行

基于脉动阵列的 NPU 在此类 `mulmat` 场景中具备较高效率，可以显著提升吞吐并降低 CPU 侧负担。

## 4. 量化方案选择

GGUF 默认量化格式更偏向通用 CPU 推理，对当前 NPU 数据通路和计算格式并不友好，因此我们没有直接复用默认量化格式，而是针对 NPU 路径设计了更适合硬件执行的量化方案。

当前采用的策略是：

- 激活：静态非对称量化（static asymmetric activation）
- 权重：静态对称 per-tensor 量化（static symmetric per-tensor weight）
- 数据格式：`W8A8`

选择该方案的原因：

- 激活使用非对称量化，能更好适应视觉侧输入分布，减少零点偏移带来的误差。
- 权重使用对称 per-tensor 量化，实现简单，硬件开销小，便于在当前 NPU 上高效实现。
- `W8A8` 在精度与硬件代价之间取得了较好的平衡，适合作为当前版本的主方案。

## 5. NPU 执行流程

当前硬件/软件协同执行链路如下：

1. CPU 负责图执行、任务切分和 NPU 调度。
2. CPU 通过 MMIO 读写 NPU 寄存器，配置本次计算的维度、地址、scale、zero-point 等参数。
3. 输入、权重和输出缓冲区放在 CMA 中，以便 NPU 侧 DMA 直接访问。
4. NPU 内部 DMA 从 CMA 搬运数据到片上缓冲。
5. 脉动阵列执行 `mulmat` 主计算。
6. 结果经过反量化/后处理后写回 CMA。
7. CPU 在需要时继续后续图执行。

这种方式下，CPU 主要承担控制职责，不再负责主矩阵乘法本身，从而减少了热点算子的 CPU 开销。

## 6. 已实现的关键优化

### 6.1 部分 mmproj `mulmat` 卸载到 NPU

针对 `mmproj` 中部分精度不敏感的线性层，进行了静态 `W8A8` 量化，并将其卸载到 NPU 执行。

这是当前吞吐提升的基础。

### 6.2 面向 NPU 的量化数据通路

为适配当前 NPU 的矩阵计算路径，实现了与 GGUF 默认格式不同的专用量化/反量化执行方式，包括：

- 静态激活 scale / zero-point 的使用
- 静态权重 per-tensor scale 的使用
- 对应的偏置、补偿项和输出恢复逻辑

### 6.3 int32-fp32 反量化单元

为了减少 CPU 端 postprocess 的时间，在 NPU 结果路径中加入了 `int32 -> fp32` 的反量化单元。

其目的在于：

- 尽量减少 CPU 端逐元素重建开销
- 缩短后处理路径
- 提高整体 `mmproj` 完成时间

### 6.4 双 DMA / 多 DMA 并行搬运

针对数据搬运开销，实现了多 DMA 并行搬运机制，使输入或中间数据可在更高程度上与计算重叠。

这类优化的目标是降低以下时间占比：

- `mvin`
- `mvout`
- 等待片上缓冲可用的空转时间

### 6.5 减少 host 侧额外拷贝

在优化过程中，对 host 侧不必要的数据复制进行了压缩与重构，尽量避免在每次推理时重复执行高成本的数据搬运。

例如：

- 减少重复的权重复制
- 尽量复用已准备好的 NPU 可访问缓冲区
- 缩短 CPU 后处理链路

### 6.6 tile 化与算子级调度优化

为了适配片上存储容量与 DMA 粒度，对 `mulmat` 做了 tile 化执行，并结合实际硬件容量调优：

- SPM 使用
- accumulator buffer 使用
- guard 区配置
- stage2 K 分块参数

这些参数直接影响吞吐、片上缓冲利用率和执行稳定性。

### 6.7 软件栈上的图融合与卸载规划

在软件侧，对 `mmproj` 图中的模式进行了识别与融合，以减少不必要的 host 侧操作与算子切换开销。例如：

- 对 `ADD(MUL_MAT, bias)` 进行融合判定
- 避免 fused `ADD` 与其 child `MUL_MAT` 被重复 offload
- 根据 bias / compensation / scale 需求选择不同执行模式

## 7. 当前收益

当前版本的主要收益体现在：

- `mmproj` 的主要 `mulmat` 热点由 CPU 转移到 NPU
- `prefill` 阶段吞吐得到实际提升
- 多模态输入下端到端延迟下降
- 对正式比赛场景而言，图像输入下的性能更接近可用状态

同时，当前版本也说明了一点：

- 对 VLM 而言，单纯优化文本解码并不足够
- 图像侧 `mmproj` 与视觉 token 扩张效应必须一起考虑

## 8. 当前限制

虽然当前版本已经可以对部分 `mmproj` 路径进行有效加速，但仍存在一些限制：

1. 目前只卸载了部分层，仍有相当一部分算子运行在 CPU 上。
2. 当前量化方案仍偏保守，目标首先是精度可用，再逐步扩大卸载范围。
3. 解码阶段仍以 CPU 上的 `GEMV` 为主，`decode` 吞吐尚未被专门优化。
4. 某些后处理和数据组织开销仍然存在，还可以继续压缩。
5. 目前的权重量化仍以 per-tensor 为主，后续仍有更优空间。

## 9. 后续优化目标

### 9.1 更优的量化方式，卸载更多层到 NPU

后续将继续研究更适合该模型和该硬件的数据表示方式，以支持：

- 更高精度保持
- 更低误差累积
- 更大范围的算子卸载
- 更高的 NPU 利用率

候选方向包括：

- 更细粒度的权重量化
- 更稳定的激活标定方式
- layer-wise / channel-wise 的混合策略
- 更适合硬件流水的 scale / zero-point 编排方式

### 9.2 实现 GEMV 单元，加速 decoding 阶段

当前 `decode` 阶段的热点更偏向 `GEMV`，与 `prefill` 里的 `GEMM` 特征不同。

因此后续将考虑在 NPU 中加入 `GEMV` 单元，用于加速：

- token-by-token 解码时的线性层计算
- 小 batch、低并行度场景下的矩阵向量乘法

这将是提升 `decode` 吞吐的关键方向。

### 9.3 进一步增强搬运与计算重叠

后续还会继续优化：

- 多 DMA 并发策略
- 计算与搬运 overlap
- 更好的 buffer ping-pong / double-buffer 机制
- 更低的 host 同步频率

### 9.4 降低 host postprocess 开销

虽然已经加入 `int32-fp32` 反量化单元，但 host 端仍有进一步压缩空间。后续会继续评估：

- 更多输出重建逻辑在 NPU 内完成
- 更少的 CMA 直接读写
- 更少的 CPU 标量后处理
- 更好的向量化与缓存友好实现

### 9.5 更好的图级融合与执行规划

后续将继续在软件栈中增强：

- pattern fusion
- layer grouping
- 更优的 offload planner
- 避免重复量化 / 反量化 / 中间格式转换

## 10. 总结

本工作所使用的 NPU 本身是一个通用 NPU，此前已经能够较好地运行传统 CNN 模型；当前工作的重点是在这一通用硬件基础上，进一步面向 VLM、LLM 场景扩展软件栈、量化方案与执行路径优化。

整体路线可以概括为：

- 找到 `prefill` 的关键瓶颈 `mmproj`
- 用适合矩阵乘法的脉动阵列 NPU 加速热点 `mulmat`
- 使用面向精度和硬件可实现性的静态 `W8A8` 量化方案
- 通过 DMA、反量化单元、tile 化和执行规划优化，减少系统级额外开销
- 在保证结果可用的前提下，逐步扩大 NPU 卸载范围

后续将继续围绕“更多层卸载 + 更强 decode 加速 + 更低系统开销”三条主线推进。
