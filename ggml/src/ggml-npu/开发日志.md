# ggml-npu 开发日志

## 1. 本轮主线调整

本轮把 `ggml-npu` 主线固定为“静态非对称 activation 量化 + 补偿项”：

- 量化参数通过离线校准提取
- 编译/plan 阶段只读取参数表，不在线重复提取
- `sum(q_w)` 补偿项在 `plan_create` 预计算
- 执行期只做轻量的 bias/补偿注入与 ACC 累加

## 2. 本轮新增/修改文件

### 2.1 ggml-npu 目录

- `ggml-npu.h`
  对外声明 `ggml_backend_npu_reg/init/buffer_type/is_npu`。
- `ggml-npu.cpp`
  后端注册、device/backend 骨架、plan 创建和执行入口。
- `ggml-npu-common.h`
  公共结构体定义，包括两级分块参数、内存空间、offset 描述、AOT plan 数据结构，以及 `head/body/tail` 执行阶段枚举；本轮把 activation 量化描述改成“dynamic/per-tensor/symmetric”配置。
- `ggml-npu-plan.h`
  计划层接口声明。
- `ggml-npu-plan.cpp`
  第一次分块、第二次分块参数、AOT offset 分配、`exec_tile` 生成、bias 融合识别、静态 weight 预打包和稳定性检查；本轮去掉了主线对静态量化表的依赖。
- `ggml-npu-quant.h`
  量化/反量化接口声明。
- `ggml-npu-quant.cpp`
  量化、解包、pack 的软件实现；本轮新增 whole-tensor dynamic symmetric activation pack 接口，并保留原静态非对称 pack 作为实验分支。
- `ggml-npu-exec.h`
  执行层接口声明。
- `ggml-npu-exec.cpp`
  基于 plan 调 runtime C API 的执行层；本轮改成运行时先计算 activation 整 tensor `scale`，再按该单一 `scale` 量化各 tile，bias 注入不再包含非对称补偿。
- `CMakeLists.txt`
  `ggml-npu` 的构建入口。

### 2.2 ggml 其他目录

- `ggml/CMakeLists.txt`

- `ggml/src/CMakeLists.txt`

- `ggml/src/ggml-cpu/ggml-cpu.c`
  增加整模型量化仿真开关；当前与 `ggml-npu` 主线最对齐的是 `GGML_NPU_QUANT_SIM=dynamic_tensor_npu`。

### 2.3 AICAS 测试与说明文件

## 3. 当前实现范围

当前 `ggml-npu` 已经具备：

- backend/device/reg 骨架
- `MUL_MAT` 和 `ADD(MUL_MAT, bias)` 识别
- 第一次分块
- 第二次分块参数
- `SPM/ACC` offset 分配
- runtime C API 执行骨架
- `Q8_0/F16/F32` 权重读取
- static weight 在 plan 创建阶段完成预打包
- whole-tensor dynamic symmetric activation pack
- ACC 跨 K 子块累加的执行框架
- 显式的 `head/body/tail/single` 执行块阶段标志
- `needs_bias / writes_output` 的编译期标记

## 4. 测试文件使用方法

### 4.1 算子级测试

文件：

- `AICAS/matmul_quant_eval.py`

用途：

- 识别 ONNX 模型中的 `MatMul/Gemm`
- 对比不同量化策略的算子级误差

示例：

```bash
source /home/pc/miniconda3/etc/profile.d/conda.sh
conda activate mlir
python3 AICAS/matmul_quant_eval.py \
  --model ../aicas/vision_encoder.onnx \
  --output-json AICAS/output/vision_encoder_matmul_quant.json \
  --output-pdf AICAS/vision_encoder_matmul_quant_report.pdf
```

### 4.2 整模型 OCRBench 测试

文件：

- `AICAS/ocrbench_gguf_quant_compare.py`

用途：

- 跑完整 `.gguf + mmproj + llama-server + OCRBench`
- 当前推荐优先比较 `baseline / dynamic_tensor_npu`

示例：

```bash
source /home/pc/miniconda3/etc/profile.d/conda.sh
conda activate mlir

python3 AICAS/ocrbench_gguf_quant_compare.py \
  --server-bin build/bin/llama-server \
  --model /home/pc/toolchain/llama_test/SmolVLM2-500M-Video-Instruct-Q8_0.gguf \
  --mmproj /home/pc/toolchain/llama_test/mmproj-SmolVLM2-500M-Video-Instruct-Q8_0.gguf \
  --dataset-mode hf \
  --eval-count 100 \
  --modes baseline,dynamic_tensor_npu \
  --output-dir AICAS/output/ocrbench_quant_compare
```

恢复功能：

- 默认开启 `--resume`
- 如果已有结果 JSON，会自动续跑
- 如果想强制全部重跑，使用 `--no-resume`

## 5. 当前限制

- 只支持 2D contiguous matmul
- 还没支持 batch/broadcast/view/permute 的完整情况
- `SPM/ACC` 容量仍是占位参数
- 还没有实现 `NpuMemPlan.cpp` 那种模块级 `first-fit + alloc/free + reuse`
- 还没把最终验证链路完整打通到真实 NPU 运行结果
- 当前 whole-tensor dynamic symmetric 路线是为了先对齐执行语义，不代表最终性能/精度已经最优
